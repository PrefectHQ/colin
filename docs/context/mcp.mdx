Model Context Protocol (MCP) connects Colin to external data sources. Through MCP, your documents can fetch live data from project trackers, databases, APIs, and other systems. Colin treats MCP resources as first-class content sources, integrating them into your dependency graph alongside local documents.

MCP servers expose resources through a standardized protocol. Colin acts as an MCP client, connecting to configured servers and fetching resources as needed during compilation. This gives your context documents access to information that lives outside your project directory.

## Configuration

Define MCP servers in your `colin.toml`:

```toml colin.toml
[project]
name = "my-context"

[[providers.mcp]]
name = "github"
command = "uvx"
args = ["mcp-server-github"]

[[providers.mcp]]
name = "linear"
command = "npx"
args = ["@linear/mcp-server"]

[[providers.mcp]]
name = "postgres"
command = "npx"
args = ["@anthropic/mcp-server-postgres"]
env = { DATABASE_URL = "${DATABASE_URL}" }
```

Each server entry specifies a command to launch the server process. Colin starts these processes on demand when documents reference their resources.

### Server Types

Colin supports two server configurations:

**Stdio servers** run as local processes and communicate via stdin/stdout:

```toml
[[providers.mcp]]
name = "filesystem"
command = "npx"
args = ["@anthropic/mcp-server-filesystem", "/path/to/data"]
```

**Remote servers** connect over HTTP/SSE:

```toml
[[providers.mcp]]
name = "remote-api"
url = "http://localhost:8080/mcp"
```

## Reading Resources

Use the MCP provider namespace to fetch content from a server. The `mcp` global is an alias for `providers.mcp`:

```markdown models/sources/github-readme.md
---
name: GitHub README
description: Latest README from the main repository
---

{{ mcp.github.resource('repo://owner/repo/contents/README.md') }}
```

Use `mcp.<server>.resource(...)` where `<server>` matches your configured name. The argument is the resource URI, which varies by server type.

### Resource URIs

Each MCP server defines its own URI scheme. Consult the server's documentation for available resources:

**GitHub server:**
```markdown
{{ mcp.github.resource('repo://owner/repo/contents/README.md') }}
{{ mcp.github.resource('repo://owner/repo/issues') }}
```

**Linear server:**
```markdown
{{ mcp.linear.resource('projects') }}
{{ mcp.linear.resource('issues?teamId=TEAM-123') }}
```

**Filesystem server:**
```markdown
{{ mcp.filesystem.resource('file:///data/config.json') }}
```

## Prompts from Servers

Some MCP servers provide prompt templates. Use `mcp.<server>.prompt()` to retrieve them:

```markdown models/analysis.md
---
name: Code Analysis
---

{% set review_prompt = mcp.github.prompt('review-checklist', repo='owner/repo') %}

{{ review_prompt }}

## Applying to Our Codebase

{% llm %}
Using the review checklist above, analyze this code:

{{ ref('sources/latest-pr').content }}
{% endllm %}
```

Prompt arguments are passed as keyword parameters after the prompt name.

## Dependency Tracking

MCP resources integrate with Colin's dependency system. When you fetch an MCP resource, Colin records this in the manifest alongside local document references.

MCP resources are tracked like any other ref. Fetching a resource records its URI in `refs_evaluated` so downstream dependencies remain accurate:

```markdown models/context/project-health.md
---
name: Project Health
---

# Project Status

{% set projects = mcp.linear.resource('projects?team=engineering') %}

{{ projects }}

## Analysis

{% llm %}
Analyze the health of these projects:
{{ projects }}
{% endllm %}
```

The manifest records MCP resources as standard refs:

```json
{
  "documents": {
    "context/project-health": {
      "refs_evaluated": ["mcp.linear://?resource=projects%3Fteam%3Dengineering"]
    }
  }
}
```

## Practical Examples

### Fetching Linear Projects

Pull project data from Linear and synthesize it into context:

```markdown models/sources/linear-projects.md
---
name: Linear Projects
description: Current engineering projects from Linear
---

{{ mcp.linear.resource('projects?team=engineering') }}
```

```markdown models/context/project-summary.md
---
name: Project Summary
description: Synthesized project status for agents
---

# Engineering Projects

{{ ref('sources/linear-projects') | extract('a summary of each active project with status and owner') }}
```

### Database Queries

Connect to a Postgres database for live data:

```toml colin.toml
[[providers.mcp]]
name = "warehouse"
command = "npx"
args = ["@anthropic/mcp-server-postgres"]
env = { DATABASE_URL = "${DATABASE_URL}" }
```

```markdown models/sources/customer-metrics.md
---
name: Customer Metrics
description: Key customer health metrics from data warehouse
---

{{ mcp.warehouse.resource('query://SELECT customer_id, health_score, last_activity FROM customer_health ORDER BY health_score ASC LIMIT 20') }}
```

### GitHub Repository Context

Build context from repository information:

```markdown models/context/repo-overview.md
---
name: Repository Overview
---

# Main Repository

## README

{{ mcp.github.resource('repo://acme/platform/contents/README.md') }}

## Recent Issues

{{ mcp.github.resource('repo://acme/platform/issues?state=open&per_page=10') }}

## Contributing Guidelines

{{ mcp.github.resource('repo://acme/platform/contents/CONTRIBUTING.md') }}
```

### Combining Multiple Sources

Synthesize information from several MCP servers:

```markdown models/skills/engineering-status.md
---
name: Engineering Status
description: Comprehensive engineering team status for support agents
---

# Engineering Status

## Active Projects

{{ ref('sources/linear-projects').content }}

## Repository Health

{% set github_issues = mcp.github.resource('repo://acme/platform/issues?state=open') %}
{{ github_issues }}

## Team Analysis

{% llm %}
Based on the project data and open issues above, provide:
1. Overall team velocity assessment
2. Top blockers across projects
3. Recommended priorities for the week

Projects:
{{ ref('sources/linear-projects').content }}

Open Issues:
{{ github_issues }}
{% endllm %}
```

## Managing Servers

Colin provides CLI commands for managing MCP server configuration.

### Adding Servers

```bash
colin mcp add github uvx mcp-server-github
colin mcp add linear npx @linear/mcp-server
```

### Listing Servers

```bash
colin mcp list
```

### Removing Servers

```bash
colin mcp remove github
```

### Testing Connections

Verify server connectivity before using resources in documents:

```bash
colin mcp test github
```

This starts the server and lists available resources, helping you discover the correct URIs to use in your documents.
